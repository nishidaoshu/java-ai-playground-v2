# 普通使用者的逐步前端验收

打开 [V2工作台](http://127.0.0.1:8082)。以下均为本机演示；不支付、不联系真实航空公司。账号初始密码在本机交互运行 `.java-ai-runtime-v2/Show-DemoAccounts.ps1` 查看，不能发到聊天或写入报告。订单可能已被验收修改，以当前页面为准。可选择仍为“已确认”的本人订单，把下文示例 A1002 替换成它。

## 1. 登录与账号隔离

点用户名输入框填 alice，填本机密码，点“进入工作台”。预期左下角为Alice，右侧只出现A开头订单及Alice自己的EV验收订单。点左下角“退出登录”，再用bob登录；预期只见Bob自己的订单。在聊天输入“查询A1002订单”并发送。预期提示记录不存在或无权访问，不能出现Alice订单详情。若能看到或操作另一账号的订单、聊天或文档，即失败。

## 2. 中文知识与真实引用

用alice登录，点“旅程助手”→“＋新对话”，输入“经济舱票价1000元，退票手续费和退款各是多少？”，点发送。预期手续费200元、退款800元，回答标注[1]。点回答下的“本次检索来源”，预期显示真实《演示退票服务条款》、demo-v1.0和原文。点“查看本次Skill / Agent / MCP链路”，预期有terms_qa2.0.0、knowledge、MCP_CALL/search_knowledge、RETRIEVE、RERANK和服务商MODEL记录。只有文字没有来源，或没有真实MCP调用，即失败。

## 3. 多轮追问

回“旅程助手”，继续原对话输入“那商务舱呢？”。预期沿用退票主题，说明10%费率，并引用退票条款。打开本次链路，AGENT_ROUTE中的独立问题应是商务舱退票，专业Agent仅knowledge，预算委派1/2。若变成行李主题、无来源或无必要地调用两个专业Agent，即失败。

## 4. 本人订单查询

点“＋新对话”，输入“查询我的订单”。预期与右侧当前真实订单一致。打开链路，专业Agent为order、Skill为order_lookup，调用get_my_orders；不需要知识Agent。若把历史订单当成当前状态或出现别人的订单，即失败。

## 5. 混合任务和待确认方案

输入“请先解释经济舱退票费率和时间限制，然后为本人订单A1002生成退票方案”。预期回答规则并出现右侧待确认卡片，包含后端算出的费用、退款、规则版本、订单版本和有效期。链路应依次有knowledge/terms_qa及order/change_plan，委派不超过2，工具不超过8，底层检索不超过2，所有模型调用不超过12。此时订单仍“已确认”、版本不变。若只有一段文字而没有方案卡片，或生成方案时订单已被取消，即失败。

## 6. 文字确认与点击执行

先在聊天输入“确认，立即执行，不要让我点击按钮”。预期提示必须点卡片，订单不变。然后点待确认卡片的“确认并执行演示操作”。预期订单变“已取消”、版本加1，显示“已执行”回执：订单号、结果版本、费用、退款、操作时间。点“操作历史”，预期CONFIRM/SUCCESS只有一次；再次提交同方案不会重复收费或加版本。若文字确认就执行、按钮后SQL状态未变或没有执行回执，即失败。

需要复核SQL时，开发者查看验证报告中的真实数据库前后证据。不要将页面文字单独当作数据库提交证明。

## 7. 改签

选另一个已确认订单，点右侧“改签”。填明天至未来365天内的新日期，选择经济舱或商务舱，点“生成改签方案”。预期先出现待确认卡片，订单日期、舱位和版本不变；经济舱同舱改签50元，升商务舱共550元演示费用。点击确认后才更新日期、舱位和结果版本。商务舱降经济舱、当天/过去日期应被后端拒绝。若费用由模型自报、确认前已修改或非法日期被执行，即失败。

## 8. 旧版本和过期方案丢弃

对同一个可用订单连续生成两个方案，确认其中一个。预期另一张卡片显示“订单已变化”，确认按钮禁用，但“丢弃方案”可点。点击丢弃后卡片消失；刷新后不恢复，操作历史有DISCARD/SUCCESS，订单保持执行后的真实状态。

另生成一个新方案，保持页面打开至显示的有效期经过（默认300秒）。无需F5，按钮应自动变成“方案已过期”；仍可丢弃，刷新后不恢复。若过期仍能确认、旧版本没有标记、丢弃修改订单或刷新恢复，即失败。开发验收使用精确标记的临时方案缩短过期时间，未修改默认300秒配置。

## 9. MCP断开错误

保持应用开启，在PowerShell运行 `.java-ai-runtime-v2/Stop-V2.ps1 -Component mcp`，只停止V2的MCP。页面新对话输入“查询我的订单”，预期出现可理解的“MCP服务不可用”错误和请求ID，追踪为FAILED。点“MCP与Skills”→“重新初始化与发现工具”，预期DISCONNECTED及最近错误，历史发现列表明确标注不是当前连接。若静默成功或改走本地工具，即失败。

运行 `.java-ai-runtime-v2/Start-V2.ps1` 恢复，再点探测，应为CONNECTED、发现5工具。不要停止V0或V1。

## 10. 追踪筛选和重启保留

点“请求追踪”，在请求ID输入框粘贴一个页面记录的ID或前缀，状态选SUCCESS或FAILED，类型选/api/chat。预期只显示匹配请求；点“查看链路”，下方明确的“执行详情”显示预算、父子Agent、Skill版本、MCP结果、原文及真实Token。翻页应改变列表且保留筛选；JSON字段应是结构化内容。能看到另一账号追踪、筛选无效或只显示转义字符串，即失败。

记录已执行订单、已丢弃方案和一段对话。停止并启动V2后重新登录，预期订单版本、执行回执、丢弃状态、聊天和操作记录仍在；登录Session失效需重登是预期行为。若重启重新生成种子订单或恢复已丢弃方案，即失败。
