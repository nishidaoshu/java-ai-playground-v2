# 待确认方案清理补充验证（2026-11-24）

原问题：方案因订单版本变化而被拒绝后，仍显示在待确认区，缺少移除入口。

现已在每张待确认卡片确认按钮下增加“丢弃方案”。过期方案和旧版本方案均可丢弃。后端校验登录、CSRF和归属，事务中锁定方案，将其标记为DISCARDED；订单不变，操作记录保留。重复请求幂等，已丢弃方案不能再确认；已执行方案不能丢弃。确认与丢弃竞争同一方案时只允许一个动作成功。

实际验证：

- TypeScript noEmit和生产构建通过。
- 真实PostgreSQL集成测试31项全部通过，较原23项新增8项丢弃相关测试；模型模拟。
- 使用独立EV测试订单，经真实准备方案接口创建方案，制造订单版本变化；浏览器先确认得到旧版本拒绝，再点击“丢弃方案”，卡片消失，刷新后仍不出现，操作历史有DISCARD/SUCCESS。
- 直接SQL验证方案为DISCARDED，订单所有检查字段保持不变；重复丢弃返回200，之后确认返回409；其他账号丢弃返回404。
- 本次更新前后的8个用户演示订单逐字段一致。仅清理了本次临时测试订单，用户现有B1003的12月21日旧方案保留，方便用户自行点击新按钮。

没有重新执行100场景模型评测；此前评测结果保持原样。原始证据：[验证JSON](../evaluation/results/discard-plan-validation.json)、target/surefire-reports及[浏览器按钮截图](screenshots/16-stale-plan-discard-button.jpg)。
